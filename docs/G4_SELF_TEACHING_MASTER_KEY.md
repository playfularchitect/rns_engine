# G4 Self-Teaching Master Key — Step 2B

The governing law is:

```text
Boundary + Rule + Residue = Pattern
Pattern + exact test + lower complete cost = promoted Rule
```

Step 2A learned which known features and interactions were promising. Step 2B
adds the missing structural teacher: remaining physical cost is preserved as an
exact object, grouped across boundaries, and converted into executable mutation
proposals.

## Immutable reality layer

The following remain outside evolution:

- frozen boundary contract;
- correctness oracle;
- timing and confidence law;
- promotion law;
- hardware and physical measurements.

A candidate may change the answer. It may not change the judge.

## Executable residue loop

```text
freeze BoundaryContract
-> evaluate executable Rule
-> store PhysicalEvidence
-> extract ExactResidue
-> discover ExactPattern across boundaries
-> create MutationProposal search objects
-> materialize them through a domain MutationRegistry
-> test with the immutable JudgeLaw
-> compare CompleteCost
-> install only certified lower-cost Rules
```

Incorrect candidates fail admission and do not receive a cheap residue score.

## Complete cost

`CompleteCost` keeps descriptive and physical costs visible:

```text
live structure
+ input residue
+ correction residue
+ ambiguity
+ mutation description
+ nondeterministic search work

reported separately from:

direct latency
graph latency
workspace
energy
```

Physical cost is never hidden inside MDL bits.

## Predictive classes

Different histories may merge when they support the same exact continuation and
conclusion. Every erased history remains recoverable in
`restoring_history_residue`. Structured correction residue can later justify a
split.

## Silent deterministic structure

Exact conclusions become `DeterministicEdge` objects bound to a contract hash
and proof ID. A continuous path of exact current edges may be compiled into a
proof-bearing `Superstep`. Repetition may nominate a superstep; only proof may
install it.

## Certificate-native continuation

`CertificateRecord` preserves:

- boundary contracts;
- candidate and coverage ledgers;
- current champions;
- correctness and physical evidence hashes;
- complete cost records;
- unresolved residues and patterns;
- predictive classes;
- merge and split decisions;
- dominated-region proofs;
- mutation proposals;
- deterministic edges and supersteps;
- proof IDs and ACTG stamp;
- Timed/Lazy cursor and parent certificate identity.

This lets a later run continue the exact proof state without repeating completed
phenotypes.
